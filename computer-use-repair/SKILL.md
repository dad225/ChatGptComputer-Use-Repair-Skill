# Computer Use 故障恢复

用户已授权在本机任务中遇到 Computer Use 故障时按此流程排查和修复。只处理桌面控制组件，不清空会话、不改账号、代理或安全设置，不上传日志。

1. 先读本会话可用的 computer-use 技能及所需文档，使用其现有通用接口复现。`sky is not defined` 先按该技能 Initialize 导入，不据此打二进制补丁。记录精确错误、目标程序、首次及重新枚举/绑定/激活后的一次重试。用户 Escape 中止、锁屏、输入占用不是二进制故障，遵守停止规则。
2. 未修复前不得凭旧截图坐标继续操作。浮动窗口要使用对应截图 ID 和局部坐标；局部菜单焦点问题不要当作整个组件故障。UE 浮动蓝图菜单关闭、窗口被恢复尺寸时，先读 [浮窗绑定与蓝图操作](references/blueprint-owned-window.md)，测试由实际返回的主 owner 窗口取得目标浮窗截图并发送输入，避免直接重新激活浮窗。
3. 确认需要原生组件修复后，读取 [本机修复资料](references/local-repair.md)。查询实际活动运行时，记录 Windows build/UBR、Codex/sky 版本、原生及 Swift helper 的路径、签名及完整 SHA-256；同版本号不等于相同二进制。系统脚本仅做取证/修补，UI 验收仍用现有 Computer Use 接口。
4. 当前已知严格配置匹配时才调用包装脚本。新运行时/未知完整哈希禁止跳过校验：继续离线适配，检查全部差异、PE、调用目标、异常展开，建立新完整哈希配置；不得仅替换哈希常量后直接运行。证据不足时写明缺口，继续其它独立任务。
5. 所有新适配先通过隔离安装/幂等/回滚/故障自动恢复/未知哈希拒绝/损坏备份拒绝测试，再备份原版并应用。说明非官方改动会使 helper 未签名；不得因此降低安全设置。只停止精确目标 helper，不杀整个 Codex/编辑器。
6. 原生文件变更后重置 JS 状态、重新初始化并重新选窗口。在两个程序各验收真实截图、无害菜单点击及截图确认、键盘操作、至少三次连续截图计时。失败即回滚本轮变更并检查回滚目标哈希/签名。拖拽故障需额外通过真实拖拽结果确认；调用无异常不能当成连线成功。用户指定 Alt+左键断线时单独验收，右键菜单断线不能替代；先查当前 Windows API 是否具备修饰键点击能力，不传被静默忽略的参数。
7. 保存版本、签名/全哈希、备份、静态/隔离/现场验证、限制和回滚命令到本机审计目录。更新可能替换补丁，不做未知版本自动追踪。恢复后继续原任务。
